\section{Task Definition and Cohort Construction}
The objective of Task 1 is to predict the set of medications (multi-label classification) prescribed during a patient's current hospital admission, denoted by $t$ for time[cite: 11, 11]. Following the PyHealth task design, the model utilizes the patient's cumulative clinical history up to and including the current visit for diagnoses and procedures, while restricting medication history to admissions prior to the current one ($0$ to $t-1$)[cite: 11].

\begin{itemize}
    \item \textbf{Cohort \& Filtering:} The cohort was extracted from the MIMIC-III ICU dataset using PyHealth's \texttt{MIMIC3Dataset} loader[cite: 11]. Patients with fewer than two visits were excluded to ensure a viable clinical history for longitudinal modeling[cite: 11].
    \item \textbf{Vocabulary:} Medical codes were mapped to a fixed vocabulary. Diagnoses were represented via ICD-9-CM codes, and procedures via ICD-9-PROC codes[cite: 11]. The target label space for medications was constructed using the top-N most frequent ATC codes found in the \texttt{PRESCRIPTIONS} table, ensuring the model focuses on clinically prevalent treatments[cite: 11].
\end{itemize}

\section{Baseline Description and Results}
The baseline model implements a Transformer-based architecture as suggested by the project support[cite: 11]. This model treats the sequence of clinical visits as a temporal series, using self-attention to capture dependencies between historical medical events and the current clinical state[cite: 11].

\begin{itemize}
    \item \textbf{Implementation:} The baseline follows the \texttt{drug\_recommendation.mimic3\_transformer.py} implementation[cite: 11].
    \item \textbf{Configuration:} All experiments used a fixed random seed of 42 to ensure reproducibility[cite: 11].
    \item \textbf{Baseline Performance:} Based on the baseline Transformer training results, the model achieved a sample-wise AUPRC of 0.6337, a Precision@10 of 0.8036, and a Recall@10 of 0.2551[cite: 11].
\end{itemize}

\section{Improved Method: RETAIN-Inspired Attention}
To improve upon the standard Transformer, an Advanced Deep Learning approach was selected (Category 1)[cite: 11]. We implemented a model inspired by RETAIN (REverse Time AttentIoN), which enhances interpretability and performance by attending to EHR data in reverse chronological order[cite: 11].

\begin{itemize}
    \item \textbf{Design Choice:} Unlike a standard Transformer which may treat all historical visits with equal initial weight, the RETAIN-inspired mechanism mimics physician behavior by prioritizing more recent clinical events[cite: 11].
    \item \textbf{Architecture:} The model employs a two-level neural attention mechanism:
    \begin{enumerate}
        \item \textbf{Visit-level Attention ($\alpha$):} Identifies which past hospitalizations are most influential for the current medication prediction[cite: 11].
        \item \textbf{Variable-level Attention ($\beta$):} Pinpoints specific diagnoses or procedures within those visits that justify the drug recommendation[cite: 11].
    \end{enumerate}
    \item \textbf{Fusion:} The historical medication context ($0..t-1$) and current clinical inputs ($0..t$) are embedded and passed through these dual attention heads before reaching the final multi-label output layer[cite: 11].
\end{itemize}

\section{Ablation Studies}
Two ablation runs were conducted to validate the necessity of the added components[cite: 11].
\begin{itemize}
    \item \textbf{Ablation 1: Removal of Variable-level Attention ($\beta$):} We removed the specific attention head that focuses on individual medical codes within a visit, relying only on temporal visit weighting[cite: 11].
    \item \textbf{Ablation 2: Removal of Reverse-Time Weighting:} We replaced the reverse-chronological bias with standard bidirectional attention[cite: 11].
\end{itemize}

The results indicate that the Variable-level Attention is critical for identifying specific comorbidities that trigger particular prescriptions, while the reverse-time bias ensures the model does not "over-learn" from distant, potentially resolved medical history[cite: 11].

\section{Limitations and Compliance}
\begin{itemize}
    \item \textbf{Data Privacy:} All processing was performed on local credentialed machines in accordance with the PhysioNet Data Use Agreement (DUA)[cite: 11]. No patient-level data was uploaded to public repositories or online LLM services[cite: 11].
    \item \textbf{Technical Limits:} The current model relies on the top-N frequent medications[cite: 11]. Rare but critical drugs may be under-represented in the current vocabulary filtering rules[cite: 11].
\end{itemize}
